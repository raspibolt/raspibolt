[Fulcrum](https://github.com/cculianu/Fulcrum) is a fast SPV server
for Bitcoin, Bitcoin Cash, and Litecoin written in C++ by Calin
Culianu. Independent benchmarks rank it as one of the quickest
Electrum server implementations available, which makes it a solid
alternative to Electrs when you want lower query latency.

This guide will help you install the latest version of Fulcrum.

## Requirements

- Bitcoin Core v0.17.0 or later, >= v28.0.0 is recommended for full Electrum Protocol v1.6 support. Bitcoin Knots is also known to work perfectly well.
- The node must have `txindex` enabled e.g. `txindex=1`.
- Caddy installed (from the same guide or standalone via `caddyserver.com`)
- Storage space for database (external backup recommended); currently takes up 192 GB (as of October 2026).

Fulcrum is a replacement for an Electrs, these two services cannot be run at the same time (due to the same standard ports used), remember to stop Electrs doing
`sudo systemctl stop electrs`. Performance issues have been found on Raspberry Pi 4 GB, it is recommended to install Fulcrum on 8 GB RAM version.

## Preparations

Make sure that you have [reduced the database cache of Bitcoin Core](https://raspibolt.org/docs/bitcoin/bitcoin-client/#after-the-initial-sync)

### Install dependencies

- With user "admin", make sure that all necessary software packages are installed
  
  ```bash
  sudo apt install libssl-dev libzmq3-dev pkg-config
  ```

### Configure Bitcoin Core

We need to set up settings in Bitcoin Core configuration file - add new lines if they are not present

- In `bitcoin.conf`, add the following line in "# ZMQ for LND and other consumers" section. Save and exit
  
  ```bash
  sudo nano /data/bitcoin/bitcoin.conf
  ```

  ```bash
  zmqpubhashblock=tcp://127.0.0.1:8433
  ```

- Restart Bitcoin Core
  
  ```bash
  sudo systemctl restart bitcoind
  ```

### Configure Firewall

- Configure the firewall to allow incoming requests

  ```bash
  sudo ufw allow 50002/tcp comment 'allow Fulcrum SSL'
  sudo ufw allow 50001/tcp comment 'allow Fulcrum TCP'
  ```

## Install Fulcrum

- Change directory to `/tmp` folder

  ```bash
  cd /tmp
  ```

- Check the latest Fulcrum release version. You can also confirm with the [release page](https://github.com/cculianu/Fulcrum/releases)

  ```bash
  VERSION=$(wget -qO- https://api.github.com/repos/cculianu/Fulcrum/releases/latest | grep -oP '"tag_name": "v\K(.*)(?=")')
  echo $VERSION
  ```

- Download the application, checksums and signature

  ```bash
  wget https://github.com/cculianu/Fulcrum/releases/download/v$VERSION/Fulcrum-$VERSION-arm64-linux.tar.gz
  wget https://github.com/cculianu/Fulcrum/releases/download/v$VERSION/Fulcrum-$VERSION-shasums.txt.asc
  wget https://github.com/cculianu/Fulcrum/releases/download/v$VERSION/Fulcrum-$VERSION-shasums.txt
  ```

- Get the public key from the Fulcrum developer

  ```bash
  curl https://raw.githubusercontent.com/Electron-Cash/keys-n-hashes/master/pubkeys/calinkey.txt | gpg --import
  ```

- Verify the signature of the text file containing the checksums for the application

  ```bash
  gpg --verify Fulcrum-$VERSION-shasums.txt.asc
  ```

  Check for a `"Good signature from "Calin Culianu (NilacTheGrim) <calin.culianu@gmail.com>"`

- Verify the signed checksum against the actual checksum of your download

  ```bash
  grep 'arm64-linux.tar.gz' Fulcrum-$VERSION-shasums.txt | sha256sum --check
  ```

  Expected output:

  ```bash
  > Fulcrum-YOUR_VERSION-arm64-linux.tar.gz: OK
  ```

- Install Fulcrum and check the correct installation requesting the version

  ```bash
  tar -xvf Fulcrum-$VERSION-arm64-linux.tar.gz
  sudo install -m 0755 -o root -g root -t /usr/local/bin Fulcrum-$VERSION-arm64-linux/Fulcrum Fulcrum-$VERSION-arm64-linux/FulcrumAdmin
  ```

- Verify it was installed correctly, and its version

  ```bash
  Fulcrum --version
  ```

### Setup data directory

Now that Fulcrum is installed, we need to configure it to run automatically on startup.

#### Create the user

A dedicated system user limits the blast radius of any bug. Adding it
to the `bitcoin` group lets Fulcrum authenticate to Bitcoin Core via
the cookie file, the same approach BTC RPC Explorer uses.

- Create the service user:

  ```bash
  sudo adduser --disabled-password --gecos "" fulcrum
  ```

- Add it to the `bitcoin` group:

  ```bash
  sudo adduser fulcrum bitcoin
  ```

- Create a symlink to /home/fulcrum/.fulcrum
  
  ```bash
  sudo ln -s /data/fulcrum /home/fulcrum/.fulcrum
  sudo chown -R fulcrum:fulcrum /home/fulcrum/.fulcrum
  ```

- Open a "fulcrum" user session
  
  ```bash
  sudo su - fulcrum
  ```

- Change to fulcrum data folder and generate cert and key files for SSL. When it asks you to put some info, press `Enter` until the prompt is shown again, is no
t necessary to put any info

  ```bash
  cd /data/fulcrum
  openssl req -newkey rsa:2048 -new -nodes -x509 -days 3650 -keyout key.pem -out cert.pem
  ```

### Configuration

RaspiBolt uses SSL as default for Fulcrum, but some wallets like [BlueWallet](https://bluewallet.io/) do not support SSL over Tor. That's why we use TCP in
configurations as well to let user choose what he needs. You may as well need to use TCP for other reasons.

- Next, we have to set up our Fulcrum configurations. Troubles could be found without optimizations for Raspberry Pi. Choose either one for Raspberry 4 GB
or 8 GB depending on your hardware. Create the config file with the following content. Save and exit

  ```bash
  nano /data/fulcrum/fulcrum.conf
  ```

  ```bash
    # RaspiBolt: fulcrum configuration
    # /data/fulcrum/fulcrum.conf

    # Bitcoin Core settings
    bitcoind = 127.0.0.1:8332
    rpccookie = /data/bitcoin/.cookie

    # Fulcrum server settings
    datadir = /data/fulcrum/fulcrum_db
    cert = /data/fulcrum/cert.pem
    key = /data/fulcrum/key.pem
    ssl = 0.0.0.0:50002
    tcp = 0.0.0.0:50001
    peering = false
    # Change it to "true" if you want to contact other servers, might speed up initial sync

    # RPi optimizations
    bitcoind_timeout = 600
    bitcoind_clients = 1
    worker_threads = 1
    db_mem = 1024.0
    # You can change this to 2048 for the first sync in a RPi with 8gb
  ```

- Exit "fulcrum" user session to return to "admin" user session
  
  ```bash
  exit
  ```

  ### Autostart on boot

Fulcrum needs to start automatically on system boot.

- As user "admin", create the Fulcrum systemd unit and copy/paste the following configuration. Save and exit
  
  ```bash
  sudo nano /etc/systemd/system/fulcrum.service
  ```

  ```bash
  # RaspiBolt: systemd unit for Fulcrum
  # /etc/systemd/system/fulcrum.service

  [Unit]
  Description=Fulcrum
  PartOf=bitcoind.service
  After=bitcoind.service
  StartLimitBurst=2
  StartLimitIntervalSec=20

  [Service]
  ExecStart=/usr/local/bin/Fulcrum /data/fulcrum/fulcrum.conf
  KillSignal=SIGINT
  User=fulcrum
  Type=exec
  TimeoutStopSec=300
  RestartSec=30
  Restart=on-failure

  [Install]
  WantedBy=multi-user.target
  ```

### Run Fulcrum

- Enable fulcrum service and start
  
  ```bash
  sudo systemctl enable fulcrum.service
  sudo systemctl start fulcrum.service
  ```

- We can check if everything goes right using these commands
  
  ```bash
  sudo systemctl status fulcrum
  sudo journalctl -f -u fulcrum
  ```

Fulcrum will now index the whole Bitcoin blockchain so that it can provide all necessary information to wallets. With this, the wallets you use no longer need
to connect to any third-party server to communicate with the Bitcoin peer-to-peer network.

DO NOT REBOOT OR STOP THE SERVICE DURING DB CREATION PROCESS. YOU MAY CORRUPT THE FILES - in case of that happening, start sync from scratch by deleting and
recreating `fulcrum_db` folder.

💡 Fulcrum must first fully index the blockchain and compact its database before you can connect to it with your wallets. This can take a few days. Only
proceed with the [Desktop Wallet Section](https://raspibolt.org/docs/bitcoin/desktop-wallet/) once Fulcrum is ready.

## Extras

### Remote access over Tor (optional)

To use your Fulcrum server when you're on the go, you can easily create a Tor hidden service.
This way, you can connect the BitBoxApp or Electrum wallet also remotely, or even share the connection details with friends and family. Note that the remote
device needs to have Tor installed as well.

- Ensure that you are logged with user "admin" and add the following three lines in the section for "location-hidden services" in the `torrc` file. Save and exit

  ```bash
  sudo nano /etc/tor/torrc
  ```

- Edit `torrc`
  
  ```bash
  ############### This section is just for location-hidden services ###
  # Hidden Service Fulcrum SSL
  HiddenServiceDir /var/lib/tor/hidden_service_fulcrum_ssl/
  HiddenServiceVersion 3
  HiddenServicePort 50002 127.0.0.1:50002

  # Hidden Service Fulcrum TCP
  HiddenServiceDir /var/lib/tor/hidden_service_fulcrum_tcp/
  HiddenServiceVersion 3
  HiddenServicePort 50001 127.0.0.1:50001
  ```

- Reload Tor configuration and get your connection address
  
  ```bash
  sudo systemctl reload tor
  ```

  ```bash
  sudo cat /var/lib/tor/hidden_service_fulcrum_ssl/hostname
  ```

  Expected output:

  ```bash
  > abcdefg..............xyz.onion
  ```

  And for TCP:
  
  ```bash
  sudo cat /var/lib/tor/hidden_service_fulcrum_tcp/hostname
  ```

    Expected output:

  ```bash
  > hijklmn..............xyz.onion
  ```

- You should now be able to connect to your Fulcrum server remotely via Tor using SSL or TCP.

### Configure BTC RPC Explorer to Fulcrum API connection and modify the service

To get address balances, either an Electrum server or an external service is necessary. Your local Fulcrum server can provide address transaction lists, balance
s, and more.

- Change to `btcrpcexplorer` user, enter to `btc-rpc-explorer` folder and open `.env` file
  
  ```bash
  sudo su - btcrpcexplorer
  ```

  ```bash
  cd btc-rpc-explorer
  ```

  ```bash
  nano .env
  ```

- Add or modify the following line. Save and exit

  ```bash
  BTCEXP_ELECTRUM_SERVERS=tls://127.0.0.1:50002
  ```

- Return to `admin` user by exiting and open `btcrpcexplorer` service
  
  ```bash
  exit
  ```

  ```bash
  sudo nano /etc/systemd/system/btcrpcexplorer.service
  ```

- Replace `"After=electrs.service"` to `"After=fulcrum.service"` parameter. Save and exit

  ```bash
  After=fulcrum.service
  ```

- Restart BTC RPC Explorer service to apply the changes
  
  ```bash
  sudo systemctl restart btcrpcexplorer
  ```

### Backup the database

If the database gets corrupted and you don't have a backup, you will have to resync it from scratch, which takes several days. This is why we recommend to make
backups of the database once in a while, on an external drive. Like this, if something happens, you'll only have to resync since the date of your latest backup.
Before doing the backup, remember to stop Fulcrum doing `"sudo systemctl stop fulcrum"`.

### Add banner to Fulcrum server (For fun!)

You can get creative when making your server banner, for example creating your own [ASCII art](https://patorjk.com/software/taag/#p=display&f=Slant&t=Fulcrum).
In [Fulcrum docs](https://github.com/cculianu/Fulcrum/blob/master/doc/fulcrum-example-config.conf) you can find additional info about making a banner in the "#
Server banner text file - 'banner'" section.

- Create and open `banner.txt` file inside Fulcrum directory

  ```bash
  sudo nano /data/fulcrum/banner.txt
  ```

- Paste your own creation into `banner.txt`. Save and exit
  
  ```bash
      ____      __
     / __/_  __/ /___________  ______ ___
    / /_/ / / / / ___/ ___/ / / / __ `__ \
   / __/ /_/ / / /__/ /  / /_/ / / / / / /
  /_/  \__,_/_/\___/_/   \__,_/_/ /_/ /_/

  server version: $SERVER_VERSION
  bitcoind version: $DAEMON_VERSION
  ```

- Open `fulcrum.conf`
  
  ```bash
  sudo nano /data/fulcrum/fulcrum.conf
  ```

- Specify path to banner at the end of your configuration file. Save and exit
  
  ```bash
  # Banner path
  banner = /data/fulcrum/banner.txt
  ```

- Restart Fulcrum
  
  ```bash
  sudo systemctl restart fulcrum.service
  ```

Now you should see your banner when connecting to Fulcrum with supported wallet (ex. Sparrow)

## For the future: Fulcrum upgrade

- As “admin” user, stop the Fulcrum service
  
  ```bash
  sudo systemctl stop fulcrum
  ```

- Create a folder and backup the database to your desired folder

  ```bash
  mkdir -p /backups/fulcrumdb
  rsync -av /home/fulcrum/.fulcrum/db/ /backups/fulcrumdb/ || true
  ```  

- Verify Bitcoin Core configuration as described in the [Configure Bitcoin Core section](fulcrum.mdx#configure-bitcoin-core) of this guide

- Download, verify and install the latest Fulcrum binaries as described in the [Install Fulcrum section](fulcrum.mdx#install-fulcrum) of this guide

- Start Fulcrum service

  ```bash
  sudo systemctl start fulcrum
  ```

## Uninstall

### Uninstall Fulcrum

Ensure you are logged with user "admin"

- Stop, disable and delete the service

  ```bash
  sudo systemctl stop fulcrum
  ```

  ```bash
  sudo systemctl disable fulcrum
  ```

  ```bash
  sudo rm /etc/systemd/system/fulcrum.service
  ```

- Delete "fulcrum" user

  ```bash
  sudo userdel -r fulcrum
  ```

- Delete fulcrum directory
  
  ```bash
  sudo rm -rf /data/fulcrum/
  ```

### Uninstall Tor hidden service

- Comment (using #) or remove fulcrum hidden service in `torrc`. Save and exit

  ```bash
  sudo nano /etc/tor/torrc
  ```

  ```bash
  ############### This section is just for location-hidden services ###
  # Hidden Service Fulcrum SSL
  #HiddenServiceDir /var/lib/tor/hidden_service_fulcrum/
  #HiddenServiceVersion 3
  #HiddenServicePort 50002 127.0.0.1:50002

  # Hidden Service Fulcrum TCP
  #HiddenServiceDir /var/lib/tor/hidden_service_fulcrum_tcp/
  #HiddenServiceVersion 3
  #HiddenServicePort 50001 127.0.0.1:50001
  ```

- Reload `torrc` config
  
  ```bash
  sudo systemctl reload tor
  ```

### Uninstall FW configuration

- Display the UFW firewall rules

  ```bash
  sudo ufw status numbered
  ```

Expected output:

```bash
    [ W] 50002/tcp                  ALLOW IN    Anywhere                   # allow Fulcrum SSL
    [ X] 50001/tcp                  ALLOW IN    Anywhere                   # allow Fulcrum TCP
    [ Y] 50002/tcp (v6)             ALLOW IN    Anywhere (v6)              # allow Fulcrum SSL
    [ Z] 50001/tcp (v6)             ALLOW IN    Anywhere (v6)              # allow Fulcrum TCP
```

- Find the "allow Fulcrum TCP" and "allow Fulcrum SSL" lines and write down the corresponding rule numbers (W, X, Y, and Z in the example)

- Delete the rule with the correct number and confirm with "yes"

  ```bash
  sudo ufw delete X
  ```
